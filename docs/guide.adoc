= PSDL user guide
:toc: left
:icons: font
:source-highlighter: rouge

A digest of the PSDL language, statement by statement. Every section is a single self-contained idea — paste the snippet into the playground editor to see what the renderer does with it.

The guide is held to a size budget on purpose: it stays a digest, not a second copy of the spec. Where the two disagree, the spec is the source of truth.

== The diagram block

[source,psdl]
----
diagram "Feeder setting" {
  …
}
----

A PSDL file contains exactly one `diagram` block. The title is a quoted string; everything else lives inside the braces. The body is a sequence of statements, each on its own line. Newlines end statements. A `#` starts a line comment that runs to end of line.

== Orientation

[source,psdl]
----
orientation horizontal   # default
orientation vertical
----

The default is `horizontal`. Vertical mirrors the same content across a vertical current axis. The criterion, margin, direction and status semantics are identical in both orientations — only the geometry changes.

== Voltage and CT

[source,psdl]
----
voltage 33 kV
ct 600/1 A
----

`voltage` declares the line-to-line voltage at the bus. `ct` declares the current-transformer ratio as primary/secondary. Both are needed when entered values in MVA or secondary amps must be compared with primary amps on the axis. `voltage` is REQUIRED when the entered quantity is MVA or kVA; `ct` is REQUIRED when the displayed quantity is secondary.

The conversions are:

* `I_A = S_MVA * 1000 / (sqrt(3) * V_kV)`
* `S_MVA = sqrt(3) * V_kV * I_A / 1000`
* `I_secondary = I_primary * S / P`
* `I_primary = I_secondary * P / S`

== Show

[source,psdl]
----
show entered
show current, mva
show current, secondary
----

The first listed quantity is the primary label below the diagram. Additional quantities appear in the same strip in the order they are listed. The first form (`entered`) is the default and keeps the engineer's authoring quantity visible.

== View

[source,psdl]
----
view report     # default in spec; renderer uses compact
view compact
view rail
----

`report` puts each criterion on its own row in the plot, with subtle status zones and a side legend. `compact` collapses the rows to a single band with near labels and short leaders. `rail` is a single value rail used in stage summaries — the implementation here treats `rail` as `compact` with a one-line status.

== Scale

[source,psdl]
----
scale linear     # default; calibrated, linear position
scale log        # calibrated, base-10 logarithmic position
scale indicative  # ordered but not calibrated; the renderer prints
                  # "INDICATIVE SPACING — NOT TO SCALE"
scale auto       # log if max/min >= 20, else linear
----

`log` requires every plotted value to be positive. The `auto` choice logs a `PSDL205_AUTO_LOG` diagnostic whenever it picks the log presentation, so the engineer can see why the axis is calibrated the way it is.

== Range

[source,psdl]
----
range auto
range all
range focus
range 3 kA to 13 kA
----

`auto` and `all` are synonyms: both include every plotted criterion, margin and selection with about 8% arithmetic padding, then round outward to a nice step from {1, 2, 2.5, 5} × 10ⁿ. `focus` narrows the range to the controlling bounds — useful in conflict studies. The explicit form gives the engineer total control. None of the forms force zero onto a linear axis; the lowest nice value wins.

== Constraints

A constraint says the selected value must lie on a particular side of a number.

[source,psdl]
----
below "Maximum load"  must 3.5 kA
below "Emergency load" must 5 kA  margin 10%
above "Minimum fault"  must 8 kA  margin 0.5 kA
above "Strong source"  should 12 kA
----

`below` means "expected below the selected value" — the engineer wants the setting to land at or above this number. `above` is the opposite. The label is free text. `must` is a hard engineering criterion; `should` is advisory. The margin can be a percentage (`10%`) or an absolute compatible quantity (`0.5 kA`); the language refuses negative margins and refuses `above` margins at or above 100%.

Margin adjustments are direction-specific:

* `below` with a 10% margin on 5 kA → effective boundary 5.5 kA (added)
* `above` with a 10% margin on 8 kA → effective boundary 7.2 kA (subtracted)
* absolute margin is added or subtracted in the same way

== Selection

[source,psdl]
----
selected "Setting" 6.5 kA
selected "Setting" 200 MVA
selected "Setting" midpoint
selected "Setting" midpoint step 0.05 kA
selected "Setting" low
selected "Setting" low step 0.05 kA
selected "Setting" high
selected "Setting" high step 0.05 kA
selected "Setting" none
----

* A literal quantity is taken at face value. The unit may be `A`, `kA`, `kVA` or `MVA`. With `kVA` or `MVA`, `voltage` is REQUIRED and the value is converted to amps before being checked against the criteria. A quantity that lands outside every `must` original criterion is reported as `DO NOT SET`.
* `midpoint` finds the centre of the preferred interval.
* `low` selects the lowest compliant setting — `mandatoryInterval.minimum`, rounded UP to the next multiple of `step`. Lands on the lower edge of the mandatory interval, almost always outside the preferred interval; reports `CAUTION`.
* `high` selects the highest compliant setting — `mandatoryInterval.maximum`, rounded DOWN to the previous multiple of `step`. Dual of `low`.
* `step` snaps the value to the grid; the unit must be `A` or `kA`. The rounding direction is fixed for `low` and `high` (up / down); for `midpoint` it follows the nearest-grid rule with exact ties away from zero.
* `none` requests analysis without selection.

`explicit` is a chosen value the engineer is taking responsibility for. `midpoint` finds the centre of the preferred interval and uses that; the `step` form rounds to the nearest settable increment, with exact ties rounded away from zero. `none` requests analysis without an automatic choice — useful for conflict diagrams.

== Custom words

[source,psdl]
----
word do-not-set    "PROHIBITED"
word caution       "REVIEW"
word recommended   "PREFERRED"
word selected      "SETTING"
word no-recommended "NO PREFERRED SETTING"
word no-compliant   "NO VALID SETTING"
----

Each of the six status words can be replaced with project-specific terminology. Each word statement may occur once. The default English labels are the keyword upper-cased with spaces. An empty string is invalid.

== Styling

[source,psdl]
----
style theme print
style palette accessible
style zones subtle
style connections pale
----

* `theme`: `light`, `dark`, `print`, `monochrome`. Default `print`.
* `palette`: `accessible`, `default`, `high-contrast`, `monochrome`. Default `accessible`. The accessible palette is colour-blind safe: teal for lower family, blue for upper family, orange for selected, red for conflict.
* `zones`: `off`, `subtle`, `full`. Default `subtle` in report view, `off` in compact. `full` doubles zone opacity.
* `connections`: `off`, `pale`, `rows`. Default `pale`.

== What the renderer shows

The encoder rules (spec §Normative visual encoding) are non-negotiable and the renderer keeps them across all themes:

* Filled circle = criterion.
* Open circle = margin boundary.
* Thick coloured segment = criterion-to-margin distance.
* Short arrow outside the open circle = acceptable direction.
* Orange line = selected value.
* Pale leader = name association.
* Pale red band = preferred conflict.
* Strong red band = mandatory conflict.

In monochrome output the renderer keeps marker fill, arrow direction, line form and text labels — colour is the only thing that changes.
