== Status

This document is the implementation-ready specification for Protection Setting Diagram Language (PSDL).
PSDL describes scalar setting-selection diagrams used in protection settings reports. It represents load, fault and other engineering criteria; percentage or absolute margins; a selected setting; compliance status; and a compact publication-quality diagram.

The processor pipeline is:

. parse source into an AST with source locations;
. resolve expressions, units, margins and conversions;
. validate structure and engineering consistency;
. analyse feasible intervals and status;
. lay out labels and markers without overlap; and
. render self-contained SVG, with optional PNG or PDF export.

== Design principles

* The language is line-oriented and intentionally small.
* Authors state engineering intent; renderers determine geometry.
* A filled dot represents a criterion and an open dot represents its margin-adjusted boundary.
* A short arrow next to the open dot points towards acceptable selected values.
* Lower criteria are normally labelled on the left; upper criteria are normally labelled on the right.
* Pale leaders associate names with marker pairs without carrying engineering meaning.
* Units are shown on criterion values, selected values and axis ticks.
* Colour reinforces meaning but never carries meaning alone.
* Autorange is the default and does not force zero onto a linear axis.

== Language overview

[source,psdl]
----
diagram "Feeder setting" {
  orientation horizontal
  voltage 33 kV
  show current, mva
  scale auto
  range auto

  below "Emergency load" must 5 kA margin 10%
  above "Minimum 2-phase fault" must 8 kA margin 10%

  selected "Selected setting" midpoint step 0.05 kA
}
----

A document MUST contain exactly one `diagram` block.
Statements are terminated by a newline or `}`. Semicolons are not used.
A line comment starts with `#` and continues to the end of the line.
Keywords and units are case-sensitive.

== Criterion semantics

=== `below`

`below` means the criterion is expected below the selected setting. The selected setting must therefore be greater than or equal to the effective boundary.

[source,psdl]
----
below "Emergency load" must 5 kA margin 10%
----

For a percentage margin, the effective boundary is:

----
effective = value * (1 + margin / 100)
----

The example resolves to `5.5 kA`.

=== `above`

`above` means the criterion is expected above the selected setting. The selected setting must therefore be less than or equal to the effective boundary.

[source,psdl]
----
above "Minimum fault" must 12 kA margin 10%
----

For a percentage margin, the effective boundary is:

----
effective = value * (1 - margin / 100)
----

The example resolves to `10.8 kA`.

=== Requirement levels

`must`:: Hard engineering criterion. Crossing the original criterion produces `do-not-set` status and an error diagnostic.
`should`:: Advisory criterion. Crossing the criterion produces `caution` status and a warning diagnostic.
`reference`:: Informational only. Plotted like any other criterion but excluded from every mandatory/preferred interval calculation — it never affects status, banding, or the zone shading. Useful for a point the reader should see on the diagram (e.g. a CT rating, a downstream relay's own pickup) without it being a condition on the selected setting. A `reference` criterion MUST NOT carry a `margin` (`PSDL006_MARGIN_NOT_APPLICABLE`) — a margin exists to define a preferred boundary, and a `reference` point has none.

A margin attached to `must` defines the preferred boundary inside the mandatory criterion. Crossing the margin but not the original `must` criterion produces `caution`.
A margin attached to `should` defines a more conservative preferred boundary; crossing either the margin or the advisory criterion remains `caution`.

=== Absolute margins

A margin MAY be an absolute compatible quantity:

[source,psdl]
----
below "Emergency load" must 5 kA margin 0.5 kA
above "Minimum fault" must 12 kA margin 1.2 kA
----

For `below`, the absolute margin is added. For `above`, it is subtracted.
A margin MUST be non-negative and MUST be less than 100% when used with `above`.

== Intervals and status

The processor converts all criteria in one diagram to the axis quantity.

[source,text]
----
mandatory_lower = maximum of all below/must original values
mandatory_upper = minimum of all above/must original values

preferred_lower = maximum of:
  all below/should original values
  all below margin-adjusted values

preferred_upper = minimum of:
  all above/should original values
  all above margin-adjusted values
----

Unbounded sides use negative or positive infinity internally.

=== Status order

`recommended`:: Selected value lies inside the preferred interval. Unlabelled by default (see below).
`caution`:: Selected value lies outside the preferred interval but inside every mandatory original criterion. Default label "Caution".
`do-not-set`:: Selected value crosses at least one mandatory original criterion. Default label "Do not set".
`no-recommended-setting`:: Preferred lower exceeds preferred upper, but mandatory lower does not exceed mandatory upper.
`no-compliant-setting`:: Mandatory lower exceeds mandatory upper. Default label "No compliant setting".
`no-selection`:: `selected ... none` was used, or no finite value was otherwise chosen, and the preferred interval is non-empty.

Status labels are presentation text and MAY be customised with `word` statements (see §Custom words). Their semantics do not change. Defaults are plain sentence case; a renderer MUST NOT force status text or other diagram labels to uppercase.

`recommended`, `no-recommended-setting` and `no-selection` are deliberately unlabelled by default:

* For `no-recommended-setting` and `no-selection`, whether a setting is missing or in conflict is a judgement for the report author, not a verdict the diagram should assert — the renderer MUST show the relevant range values (see below) instead of a status word.
* For `recommended`, a status word would only be announcing back what the marker sitting in the green zone (and its zone percent annotations, see §Selected-setting percentages) already shows — the renderer SHOULD NOT show a status word or any other footer text for this status.

A `word recommended` or `word no-recommended` statement remains valid PSDL but has no effect on the default renderer's display, since no verdict word is shown for either status.

=== Conflicting preferred constraints

image::example-preferred-conflict.svg[Preferred constraints conflict,100%]

When the preferred interval is empty but the mandatory interval exists (`no-recommended-setting`):

* the renderer MUST NOT show a status word;
* the crossed preferred boundaries MUST be visible as range values;
* the renderer MUST NOT show a normal automatic selected marker; and
* an explicit user-selected value MAY be shown with `caution` status.

=== No selection

When `selected ... none` is used and the preferred interval is non-empty (`no-selection`):

* the renderer MUST NOT show a status word;
* the renderer MUST show the preferred range (or, if the preferred interval is unbounded on a side, the mandatory range) as plain range values; and
* the renderer MUST NOT show a selected marker.

=== Conflicting mandatory constraints

image::example-mandatory-conflict.svg[Mandatory constraints conflict,100%]

When the mandatory interval is empty (`no-compliant-setting`):

* the renderer MUST show the `no-compliant-setting` status label;
* no automatic selected value may be generated;
* the two controlling mandatory criteria MUST be identified; and
* the absolute conflict MUST be reported.

== Selected value

The selected statement has five forms.

[source,psdl]
----
selected "Selected setting" 6.5 kA
selected "Selected setting" 200 MVA
selected "Selected setting" midpoint
selected "Selected setting" midpoint step 0.05 kA
selected "Selected setting" low
selected "Selected setting" low step 0.05 kA
selected "Selected setting" high
selected "Selected setting" high step 0.05 kA
selected "Selected setting" none
----

* A literal quantity is taken at face value. The unit may be `A`, `kA`, `kVA` or `MVA`. When the value is in `kVA` or `MVA` the `voltage` statement is REQUIRED (or the quantity must carry its own `@ X kV`, see §Per-quantity voltage) and the renderer converts to amps. A quantity that lands outside every `must` original criterion is reported as `do-not-set` and emits a `PSDL109_SELECTED_OUTSIDE_MUST` diagnostic.
* `midpoint` selects the midpoint of the finite preferred interval. If the preferred interval is unbounded or empty, midpoint selection fails and emits `PSDL111_MIDPOINT_UNAVAILABLE`.
* `low` selects the *lowest* compliant setting: it equals `mandatoryInterval.minimum` (the highest `must below` original) rounded UP to the next multiple of `step`. `low` fails with `PSDL110_MANDATORY_INTERVAL_EMPTY` when the mandatory interval is empty. The result sits on the lower edge of the mandatory interval, so it is usually outside the preferred interval — `low` selections are almost always `caution` and the renderer reports the headroom against the preferred lower boundary.
* `high` is the dual of `low`: it equals `mandatoryInterval.maximum` (the lowest `must above` original) rounded DOWN to the previous multiple of `step`. Same diagnostics and same status behaviour. Use `high` when the engineer wants the *highest possible* compliant setting — the relay will be the most sensitive, but still clear the must-above criteria.
* `step` rounds the chosen value to the nearest settable increment, with exact ties rounded away from zero. The unit must be `A` or `kA`. A `step` value that is not positive emits `PSDL112_STEP_INVALID`. For `low` and `high` the rounding direction is fixed (up for `low`, down for `high`); for `midpoint` it follows the nearest-grid rule.
* `none` requests analysis without selection and is useful for conflict diagrams.

== Selected-setting percentages

For a preferred-interval boundary `B` and selected value `S`, the renderer SHOULD report a single signed headroom percentage — not a ratio paired with a separate clearance figure:

----
signed_percent = (S - B) / B * 100
----

The sign follows the number line, not "is this safe": positive means `S` is numerically above `B`, negative means numerically below. A lower boundary therefore normally reads positive (`S` sits above the floor) and an upper boundary normally reads negative (`S` sits below the ceiling) — the label states the boundary value and its signed percentage together, for example:

----
5.5 kA +15.5%
7.2 kA -11.8%
----

Separately, each boundary has a `crossed` state — whether `S` is actually on the wrong side of it for its family (`S < B` for a `below` criterion, `S > B` for an `above` criterion). This is independent of the sign above: a `caution` selection that has exceeded an upper boundary shows a *positive* percentage (`S` is numerically greater than `B`) while still being crossed. A renderer MUST colour each label by `crossed` (green when not crossed, caution/conflict colour when crossed), not by the sign of the percentage.

While every mandatory criterion is satisfied (`recommended` or `caution` status), the renderer SHOULD report both preferred-interval edges, not just the nearer or controlling one — this is what lets a reader see the full picture of headroom on both sides at once.
Once a mandatory criterion is crossed (`do-not-set`), the renderer SHOULD report only the crossed mandatory boundary — the healthy far side is not useful context once a hard limit is already broken.

A renderer MUST annotate the preferred (green) zone itself with these labels, adjacent to the zone, rather than place them in a text line elsewhere on the page — the zone annotation is the ONE place they appear, so the status detail line MUST NOT repeat them. The selected-value label MUST be positioned above this annotation (and above a `secondary axis top`, if present), since it is the more important of the two and reads first.

* Vertical orientation: each label is positioned at its OWN boundary's actual axis position, not at a shared "top/bottom of band" position — a renderer MUST NOT anchor both labels to whichever end of the band has more room, since on a tall band that can place a label far from the value it names (e.g. the lower boundary's label drifting up next to the upper boundary). Each label independently prefers just inside the band next to its own marker; if that would land on the selected line or its label, it MUST fall back to just outside the band on its own side instead, still adjacent to the band and still tied to its own position. If a label's own position leaves no clear spot on either side (a very short band with the selection on top of it), the renderer MAY drop that one label; if both labels end up within a row of each other, merge them into one line rather than overlap.
* Horizontal orientation: the band spans the full plot height, so labels are drawn in their own row immediately adjacent to the plot instead (with the selected label, and any `secondary axis top`, stacked above that row). When two labels would collide at their true x positions (a narrow preferred interval), a renderer SHOULD merge them into a single combined label rather than let them overlap or arbitrarily drop one, e.g. `5.5 kA +15.5% · 7.2 kA -11.8%`.

== Quantities and expressions

Supported units are:

`A`, `kA`:: RMS current.
`kVA`, `MVA`:: Three-phase apparent power.
`kV`:: Line-to-line voltage, allowed only in `voltage`.
`%`:: Margin only.

Expressions support positive decimal numbers, parentheses, multiplication and division:

[source,psdl]
----
above "Minimum fault" must 1.1 * 10 kA margin 10%
below "Load" must (24 / 1.1) MVA margin 0.5 MVA
----

Addition, subtraction, variables, functions and implicit multiplication are not part of version 1.0.
Division by zero is an error.

=== Per-quantity voltage

Any quantity MAY carry an inline voltage, overriding the diagram's declared `voltage` for that one quantity's kVA/MVA conversion:

[source,psdl]
----
below "11 kV side" must 50 MVA @ 11 kV
above "33 kV side" must 20 MVA @ 33 kV
----

This lets one diagram compare criteria measured at different voltage levels — either side of a transformer, for example — without a single diagram-wide voltage being sufficient. `A` and `kA` quantities MAY also carry `@`, though it currently has no effect on the resolved value: current is already in amps and needs no voltage to convert. If every kVA/MVA quantity in a diagram carries its own `@`, the diagram-level `voltage` statement becomes unnecessary. Where both are present, the inline `@` on a quantity takes precedence over the declared `voltage` for that quantity.

A renderer MUST show the override voltage in brackets next to a value it produced, e.g. `5.5 kA (@ 11 kV)`, for every kVA/MVA quantity — criterion or selected setting — that carried its own `@`. This does not apply to an `A`/`kA` quantity's `@`, since it has no effect on the value shown.

== Secondary axis

[source,psdl]
----
secondary axis top kA
secondary axis top MVA
secondary axis bottom MVA @ 11 kV
----

`secondary axis` is an OPTIONAL singleton that adds a second calibrated axis, relabelling the plot's existing physical positions in a different quantity and/or voltage rather than plotting anything new.

* `top` or `bottom` chooses which side of the plot the second axis is drawn on. Horizontal orientation only — a renderer MUST ignore `secondary axis` in vertical orientation.
* `kA` mirrors the primary axis's own values one-for-one; no voltage is used.
* `MVA` converts each position using, in order: its own `@ X kV` override if present, otherwise the diagram's declared `voltage`. `MVA` with neither available is an error (`PSDL107_UNIT_INCOMPATIBLE`), the same as any other kVA/MVA quantity without a voltage to convert with.
* The secondary axis's own tick values are chosen to be "nice" round numbers IN ITS OWN quantity, then each is mapped back to the physical position that value corresponds to on the shared axis — they are not expected to land on the same positions as the primary axis's ticks.

== Conversions

For three-phase apparent power at line-to-line voltage:

----
I_A = S_MVA * 1000 / (sqrt(3) * V_kV)
S_MVA = sqrt(3) * V_kV * I_A / 1000
----

For `ct P/S A`:

----
I_secondary = I_primary * S / P
I_primary   = I_secondary * P / S
----

`voltage` is REQUIRED when current and MVA values must be compared, UNLESS every kVA/MVA quantity that needs converting carries its own `@` voltage override (see §Per-quantity voltage).
`ct` is REQUIRED when secondary current is requested.
The processor MUST preserve entered values and SHOULD return calculated primary current, secondary current and MVA where possible.

== Diagram statements

=== Orientation

[source,psdl]
----
orientation horizontal
orientation vertical
----

Default: `horizontal`.
Both orientations MUST use the same criterion, margin, direction and status semantics.

image::example-report-vertical.svg[Vertical feeder setting view,65%]

=== Displayed quantities

[source,psdl]
----
show entered
show current, mva
show current, secondary
----

`entered` preserves the authored quantity as the primary label.
`current` shows equivalent primary current.
`mva` shows equivalent MVA.
`secondary` shows CT secondary current.
The first listed quantity is primary. Additional quantities are visually secondary.

When the selected setting's MVA was converted using its own per-quantity `@` override (§Per-quantity voltage) rather than the diagram's nominal `voltage`, the two are not directly comparable to another set point converted at the nominal voltage — the same current reads as a different MVA figure at each voltage. A renderer SHOULD show the nominal-voltage MVA in brackets alongside the primary figure, e.g. `80 MVA (240 MVA @ 33 kV nominal)`, so set points from either side of a transformer stay comparable. Omitted when there is no override, or the override equals the nominal voltage.

=== View

[source,psdl]
----
view report
view compact
view rail
----

`report`:: Separate criterion rows, subtle status zones, connection leaders and full status detail.
`compact`:: Near labels, short leaders, no mandatory zone shading, and one-line status summary.
`rail`:: One value rail, intended for stage summaries. Only controlling local arrows and percentages are prominent.

Default: `compact`.

image::example-compact-horizontal.svg[Compact horizontal view,100%]

=== Scale

[source,psdl]
----
scale linear
scale log
scale indicative
scale auto
----

`linear`:: Calibrated linear position.
`log`:: Calibrated base-10 logarithmic position. Every plotted value MUST be positive.
`indicative`:: Ordered, non-calibrated spacing with minimum marker separation. The renderer MUST show a notice equivalent to "Indicative spacing — not to scale".
`auto`:: Select linear unless `maximum positive value / minimum positive value >= 20`, then select logarithmic. The selected scale MUST be labelled.

Default: `auto`.

image::example-log-horizontal.svg[Logarithmic wide-range view,100%]

=== Range

[source,psdl]
----
range auto
range all
range focus
range 3 kA to 13 kA
----

`auto`:: Include every plotted criterion, margin and selected value with approximately 8% padding and nice outward rounding.
`all`:: Synonym for `auto`, retained to emphasise inclusion of all values.
`focus`:: For conflict status, focus on controlling boundaries. Otherwise focus on controlling preferred boundaries and the selected value; remote values use explicit off-range markers.
`quantity to quantity`:: Authoritative explicit limits.

Default: `auto`.
Zero is not forced onto a linear axis.
A renderer MUST NOT omit a value without an explicit off-range marker containing the exact value and unit.

== Custom words

[source,psdl]
----
word do-not-set "Prohibited"
word caution "Review"
word recommended "Preferred"
word selected "Setting"
word no-recommended "No preferred setting"
word no-compliant "No valid setting"
----

Each word statement MAY occur once. The default English words are short, plain sentence-case phrases; renderers MUST NOT transform them to uppercase.
An empty string is invalid.
`recommended` and `no-recommended` configure text that the default renderer never displays (see §Status order) but MAY be used by renderers that choose to show a status word for those statuses.

== Styling

Core PSDL keeps styling compact. The following optional properties are portable:

[source,psdl]
----
style theme print
style palette accessible
style zones subtle
style connections pale
style title on
----

`theme` values: `light`, `dark`, `print`, `monochrome`.
`palette` values: `accessible`, `default`, `high-contrast`, `monochrome`.
`zones` values: `off`, `subtle`, `full`.
`connections` values: `off`, `pale`, `rows`.
`title` values: `on`, `off`. When `off`, the renderer MUST NOT draw the diagram title, and SHOULD reclaim the vertical space it would have used — useful when a report's own caption already names the diagram.

Defaults are `print`, `accessible`, `subtle` for report view, `pale` connections, and `title on`.
An implementation MAY add namespaced style extensions. Unknown unnamespaced style properties are errors.

== Normative visual encoding

* Criterion: filled circle.
* `reference` criterion: open circle in a neutral colour, distinct from both criterion families — it is not a condition and MUST NOT be drawn with a family colour or a margin bar.
* Margin-adjusted boundary: open circle with coloured outline.
* Criterion-to-margin distance: thick coloured segment.
* Acceptable direction: short arrow immediately outside the open circle.
* Selected value: orange or otherwise high-contrast line and filled marker.
* Lower criterion family: teal in the accessible palette.
* Upper criterion family: blue in the accessible palette.
* Name association: pale leader with no arrowhead.
* Preferred conflict: pale red conflict band and explicit text.
* Mandatory conflict: stronger red conflict band and no selected marker.

A renderer MUST retain marker fill, arrow direction, line form and text labels in monochrome output.

=== Numeric precision

A criterion, margin boundary, or mandatory/preferred range value ("a condition") displayed in kA MUST show exactly one decimal place.
The selected setting displayed in kA MUST show exactly two decimal places — one more than a condition, since it is the number that actually gets dialled into a relay.
Values below 1000 A displayed in A are shown as entered, with no forced decimal places.
This applies to displayed values only; internal computation MUST NOT be rounded to these precisions.

== Layout and collision avoidance

The renderer MUST complete layout before emitting final SVG geometry.
The following algorithm is normative in outcome and informative in implementation detail:

. Compute marker positions from the resolved scale.
. Allocate one row per criterion in report view.
. Attempt near-label placement next to the marker pair.
. Measure text bounds using the actual font metrics.
. If a label collides, move it vertically within its row and extend a short pale leader.
. If the leader would exceed 25% of plot width, move the label to the appropriate outside gutter.
. If gutter leaders are difficult to trace, use alternating pale row strips.
. Stagger numeric labels above and below markers before moving criterion names.
. Combine identical positions into one marker with `×N` and list labels in the gutter.
. Never allow a label to overlap another label, marker, selected line, status callout or plot boundary.
. Never allow a pale association leader to cross another criterion row.

The plot MUST reserve asymmetric gutters based on measured labels rather than fixed equal margins.
The renderer SHOULD keep five to eight major ticks and MUST include units on visible ticks.

== Autorange

For linear auto range:

----
minimum = min(all original values, margins, selected)
maximum = max(all original values, margins, selected)
span = maximum - minimum
raw_min = minimum - 0.08 * span
raw_max = maximum + 0.08 * span
----

The renderer rounds outward using a nice step from `1, 2, 2.5, 5 × 10^n` and targets five to eight major ticks.
When all values are equal, a symmetric non-zero range is created around the value.

For log auto range, limits round outward to useful decade or partial-decade ticks.
For conflict focus range, the controlling interval receives at least 50% of its width as padding, subject to a minimum readable span.

== Validation diagnostics

Each diagnostic contains a stable code, severity, message and source span.

=== Parse and structure errors

`PSDL001_UNKNOWN_STATEMENT`:: Unknown statement or keyword.
`PSDL002_DUPLICATE_SINGLETON`:: Duplicate orientation, voltage, CT, view, scale or range.
`PSDL003_STRING_REQUIRED`:: Missing or invalid quoted label.
`PSDL004_EXPRESSION_INVALID`:: Malformed arithmetic expression.
`PSDL005_UNIT_UNKNOWN`:: Unsupported unit.
`PSDL006_MARGIN_NOT_APPLICABLE`:: A `reference` criterion carries a `margin`.

=== Engineering errors

`PSDL101_NO_CONSTRAINT`:: Diagram contains no criteria.
`PSDL102_VALUE_NEGATIVE`:: Criterion, selection or absolute margin is negative.
`PSDL103_MARGIN_PERCENT_RANGE`:: Percentage margin is negative or an above margin is at least 100%.
`PSDL104_DIVIDE_BY_ZERO`:: Expression divides by zero.
`PSDL105_VOLTAGE_REQUIRED`:: Current/MVA conversion required without voltage.
`PSDL106_CT_INVALID`:: CT ratio side is not positive.
`PSDL107_UNIT_INCOMPATIBLE`:: Quantity cannot be converted to the axis quantity.
`PSDL108_LOG_NONPOSITIVE`:: Logarithmic scale contains a non-positive value.
`PSDL109_SELECTED_OUTSIDE_MUST`:: Selected value crosses mandatory original criterion.
`PSDL110_MANDATORY_INTERVAL_EMPTY`:: No compliant setting exists.
`PSDL111_MIDPOINT_UNAVAILABLE`:: Preferred interval is empty or unbounded.
`PSDL112_STEP_INVALID`:: Selection step is non-positive or incompatible.

=== Warnings

`PSDL201_SELECTED_OUTSIDE_PREFERRED`:: Selected value is cautionary.
`PSDL202_PREFERRED_INTERVAL_EMPTY`:: No recommended setting exists.
`PSDL203_LABEL_DENSE`:: Renderer required gutter or row-strip fallback.
`PSDL204_OFF_RANGE_MARKER`:: Focus range omitted a remote value from calibrated plot area.
`PSDL205_AUTO_LOG`:: Auto scale selected logarithmic presentation.

=== Informational diagnostics

`PSDL301_SELECTED_DEFAULTED`:: Midpoint selection applied.
`PSDL302_SELECTION_SNAPPED`:: Selected value rounded to a step.
`PSDL303_RANGE_AUTOFIT`:: Axis limits derived.
`PSDL304_CONVERSION_APPLIED`:: Display quantity differs from entered quantity.
`PSDL305_LOW_SELECTED`:: Low selection applied — the chosen value is the lowest compliant setting (`mandatoryInterval.minimum` rounded up to `step`).
`PSDL306_HIGH_SELECTED`:: High selection applied — the chosen value is the highest compliant setting (`mandatoryInterval.maximum` rounded down to `step`).

== Resolved result model

A processor SHOULD return a machine-readable object equivalent to:

[source,json]
----
{
  "title": "Feeder setting",
  "status": "recommended",
  "axis": {
    "quantity": "current",
    "unit": "kA",
    "scale": "linear",
    "minimum": 3.0,
    "maximum": 13.0
  },
  "mandatoryInterval": { "minimum": 5.0, "maximum": 8.0 },
  "preferredInterval": { "minimum": 5.5, "maximum": 7.2 },
  "selected": {
    "label": "Selected setting",
    "value": 6.35,
    "unit": "kA",
    "defaulted": true,
    "primary_A": 6350,
    "secondary_A": 10.583,
    "MVA": 362.9
  },
  "controlling": {
    "lower": { "label": "Emergency load", "boundary": 5.5 },
    "upper": { "label": "Minimum 2-phase fault", "boundary": 7.2 }
  },
  "diagnostics": []
}
----

Calculated values are rounded for display only; implementations MUST retain sufficient internal precision for validation.

== Conformance requirements

A conforming processor MUST:

* parse the normative grammar;
* evaluate multiplication, division and parentheses deterministically;
* apply direction-specific margin calculations;
* derive mandatory and preferred intervals;
* implement all five statuses;
* reject automatic selection when no valid interval exists;
* implement horizontal and vertical rendering;
* implement linear and logarithmic calibrated scales;
* implement auto range without forcing zero;
* render criterion and margin dots on the same row or column;
* render local direction arrows beside margin dots;
* avoid overlaps using measured text bounds; and
* emit stable diagnostics.

A conforming report renderer SHOULD additionally implement compact and rail views, indicative scale, PNG export, conversion labels and accessible themes.
